# 个人投资决策工作流（advisor）

一套跑在你本机的、**规则可解释、结论可执行**的投资决策流程：用 akshare 抓公开数据 → 用确定性规则打分筛选 → 按保守/稳健/激进三档风险偏好给出**具体买什么、买多少、什么价位买卖、什么时候调仓**。支持导入一次持仓，之后每天输出的是**从当前持仓到目标组合的调仓单**，不用重复填本金。

> 重要声明：本项目是**决策辅助工具**，不是投资顾问。所有结论由规则机械生成，不构成任何投资建议。
> 先读 [风险与局限](#十风险与局限)，再用不超过总资产 30% 的钱做验证。

---

## 一、它解决什么问题

市面上的开源项目大致分两类：一类只给数据（akshare/tushare），一类只给"AI 研报"（TradingAgents 等，输出是自然语言，无法核对）。本项目补的是中间那一层：

| 你需要的 | 本项目的做法 |
|---|---|
| 买什么 | 规则打分后取前 N 名，列出**代码、名称、最新价** |
| 什么价买 | 给出**限价挂单价格**（现价折扣）与放弃条件 |
| 买多少 | 按本金算**手数**（可转债 10 张起、ETF/股票 100 份起）与**占比** |
| 什么时候卖 | 每只标的有**止损价、止盈价** |
| 为什么是它 | 每只标的有**一行理由**（双低值/溢价率/股息率/动量） |
| 我已经有持仓怎么办 | 导入一次持仓快照，之后只输出"从当前持仓到目标组合"的调仓单，不用每次重填 |
| 没标的怎么办 | 明确写出"无满足条件的标的"的原因，钱留现金，不硬凑 |

## 三·五、持仓模式：录一次，之后只算"调仓"（本次新增）

以前每次都要重填本金，因为它只会"从零建仓"。现在有一个本地账本（SQLite），
持仓、现金、成本价只录一次，之后每天分析的是"从当前持仓到目标组合，该买/卖多少"。

### 1) 导入持仓（一次性）

准备一个 CSV（列名支持中英文，asset 可省略，会按代码自动识别）：

~~~csv
code,name,quantity,cost_price,asset
sh512800,银行ETF,10000,0.82,etf
113046,金田转债,40,108.5,cb
600011,华能国际,700,6.5,stock
~~~

~~~powershell
python -m advisor.cli holdings import --file holdings.csv --cash 50000
python -m advisor.cli holdings list --prices
~~~

模板见根目录 `holdings.example.csv`（复制改数即可）。
--cash 是券商账户里的可用现金。导入是"持仓快照"，会覆盖上一次快照；
不传 --cash 则保留原现金。数据在 data/advisor.db，删掉它等于清空账本。

### 2) 之后每天只跑这一条

~~~powershell
python -m advisor.cli advise --tier balanced
~~~

- --mode auto（默认）：有持仓就调仓，没持仓就新建仓；
- --mode build：忽略持仓，按 --capital 重新建仓；
- --mode rebalance：强制调仓，没持仓会报错；
- --keep-unknown：持仓里不在本期候选池的标的保留，不自动清仓（默认会清）。

输出会多出"当前持仓"和"调仓清单"两节，买入/卖出都带**差额数量、委托价、金额、理由**。

### 3) 记账（可选）

~~~powershell
python -m advisor.cli trade buy  --code sh512800 --qty 1000 --price 0.85 --fee 5
python -m advisor.cli trade sell --code sh512800 --qty 500  --price 0.95 --fee 5
python -m advisor.cli cash 30000
~~~

买卖会自动更新持仓均价、已实现盈亏和现金。注意：界面上的"保存持仓"是**快照覆盖**，
会清空交易流水；想连续记账就用 trade，不要反复在界面上点保存。

### 4) 为什么这样设计

- **账本是事实，持仓是视图**：positions 不单独存表，永远由 transactions 重放推导，
  所以不会出现"持仓表和交易表对不上"；
- **回测与实盘同源**：调仓用的 plan_rebalance() 是纯函数，输入是目标组合 + 当前持仓 + 现金，
  以后接模拟盘/回测可以直接复用；
- **先卖后买、现金约束**：卖出回款先到账，买入不够就按比例缩量，不会出现"指令总额超过可用资金"。

## 四、可视化界面（推荐日常用这个）

不想敲命令行就双击 **`start_ui.bat`**，浏览器会自动打开 `http://127.0.0.1:8765/`；也可以命令行启动：

```powershell
python -m advisor.cli ui --port 8765          # 加 --no-browser 不自动开浏览器
```

界面能力：

| 区域 | 作用 |
|---|---|
| 1 · 风险档位卡片 | 点卡片切换保守/稳健/激进，填本金，点"开始分析" |
| 2 · 我的持仓 | 现金 + 持仓表格，可直接增删改；保存后自动按"调仓"模式分析。右上角可选是否清仓不在候选池的持仓 |
| 运行日志 | 实时显示抓数进度（哪一步慢一目了然） |
| 3 · 当前持仓 | 调仓模式下显示数量、成本、现价、市值、浮盈、权重 |
| 4 · 调仓清单 | 买/卖/持有、当前→目标数量、差额、委托价、金额、理由 |
| 5 · 目标组合 | 调仓后的目标持仓（新建仓模式下就是买入清单） |
| 6 · 资产配置 | 目标权重 vs 实际权重对照 |
| 7 · 执行清单 | 按优先级排好的动作（卖出 / 买入 / 持有 / 现金） |
| 8 · **AI 风险复核** | 一键调用 DeepSeek 对组合挑刺；也可只复制 prompt 贴给任意模型 |
| 9 · 日报与备选池 | 完整 Markdown 日报、各资产类别候选前 10、回测结果 |

技术细节：界面是**单页 HTML + 一个原生 JS 文件 + Python 标准库 HTTP 服务**（不装 Flask/FastAPI），只监听 `127.0.0.1`，
分析任务跑在后台线程，前端轮询进度，所以不会卡住页面。停止：关闭那个命令行窗口，或 Ctrl+C。

### 4.1 配置 DeepSeek（AI 风险复核）

点右上角【设置】，填 **API Key**（`sk-` 开头，在 platform.deepseek.com 申请）、Base URL（默认 `https://api.deepseek.com`）、模型
（`deepseek-chat` 快而便宜 / `deepseek-reasoner` 推理更强但更慢更贵）。

- Key 只保存在本机的 `data/settings.json`，不会上传到任何第三方；也可以用环境变量 `DEEPSEEK_API_KEY` 代替；
- 界面上只显示掩码（如 `sk-abc…cdef（25 位）`），留空保存则不改动已存的 Key；
- 我实测过三条链路：未配置 → 提示"未配置 Key"；Key 错误 → 返回 DeepSeek 的 `HTTP 401 Authentication Fails`；网络不通 → 提示检查 base_url。**接口是通的，只差你的 Key**；
- AI 的定位是**风险挑刺**（强赎、ST、评级下调、行业集中度、组合相关性），明确禁止它给价格预测，结果可选另存为 `reports/<日期>_<档位>_AI风险复核.md`。

> 为什么不让 AI 直接选票：LLM 给不出可复核的仓位与价位，同一天问两次答案可能不同。规则负责"选什么、买多少"，
> AI 负责"这笔交易最可能怎么亏钱"。两者分工，才不会互相污染。

## 五、报告怎么读（章节按实际出现自动编号）

调仓模式与新建仓模式的章节号会按实际出现的章节自动排，内容顺序一致：

1. **资产配置（目标 vs 实际）**：ETF / 可转债 / 红利价值股 / 成长股 / 其他个股 / 现金。调仓模式下"实际"来自你当前持仓的市值，不是目标值。
2. **当前持仓**（调仓模式）：代码、名称、数量、成本价、现价、市值、浮盈、浮盈%、权重%。
3. **调仓清单**：动作（买入/卖出/持有）、当前数量、目标数量、差额、委托价、金额、预估费用、理由；下面会列"调仓提示"（现金偏差、无行情按成本价估算等）。
4. **执行清单**：按优先级排序，卖出在前、买入在后，带触发条件。
5. **不同本金的手数对照**（仅新建仓模式）：1000 / 5000 / 1 万 / 5 万 / 10 万 各能买几手。
6. **备选池**：每类资产前 10 名，用于轮动替换。
7. **规则回测**（加 --with-backtest 时）：策略 vs 沪深300。
8. **数据体检**：每个数据源是"在线/缓存/失败"，失败时报告会明确告警。
9. **风险声明**：机械规则、不构成投资建议、未考虑停牌/强赎/违约等。
10. **AI 二次解读 prompt**：一段可直接丢给任意大模型的提示词，让它做风险挑刺（强赎、ST、评级下调、集中度），而不是让它预测价格。

## 六、三档规则到底差在哪

| 维度 | 保守型 | 稳健型 | 激进型 |
|---|---|---|---|
| 目标收益 / 回撤容忍 | 3~6% / ≤8% | 6~10% / ≤15% | 12%+ / ≤30% |
| 资产配置 | 债 50% + ETF 20% + 红利 10% + 现金 20% | ETF 35% + 债 30% + 红利 20% + 成长 5% + 现金 10% | ETF 40% + 成长 25% + 债 20% + 现金 10% |
| 可转债准入 | ≤118 元，溢价 ≤35%，评级 ≥AA- | ≤130 元，溢价 ≤50%，评级 ≥A+ | ≤145 元，溢价 ≤60%，评级 ≥A |
| ETF 准入 | 只允许低风险标签（债券/红利/沪深300/标普） | + 中风险（银行/医药/消费/黄金） | + 高风险（纳指/券商/半导体/军工/新能源） |
| ETF 动量窗口 | 20 日（持 4 只） | 60 日（持 3 只） | 60 日（持 3 只），且要求动量为正 |
| 止损 | ETF 8% / 债 8% / 红利 12% | 12% / 12% / 15% | 15% / 15% / 20% |
| 止盈（减半仓） | 25% / 20% / 30% | 35% / 30% / 40% | 10% / 15% / 20% |
| 调仓节奏 | 每月首个交易日 | 每月首个交易日 | 每两周首个交易日 |

### 打分公式（全部可核对）

**可转债**（满分 100）
```
双低值 = 现价 + 转股溢价率(%)
score = 45×(双低越低越好) + 20×(价格越低越好) + 20×(溢价越低越好) + 15×评级
硬过滤：剔除正股含 ST、剔除低于流动性阈值、剔除评级不达标
止损 = 买入价×(1-止损比例)；止盈 = min(买入价×1.3, 强赎触发价)
```

**ETF**
```
score = 45×动量 + 15×短动量 + 20×(站上20/60日线) + 10×低波动 + 10×(距60日高点近)
保守档额外规则：先配 1 只债券 ETF 作底仓，再用红利/宽基补齐
（避免纯动量排序把货币/短融类"低波动陷阱"排到第一位）
```

**红利价值股**（候选为银行/能源/公用/建材/消费等大票）
```
score = 40×股息率 + 20×低PB + 20×趋势 + 20×(距高点回撤小)
硬过滤：必须站上 20 日线，剔除 60 日跌幅超 45% 的
```

**成长/主题股**（激进档）
```
score = 35×60日动量 + 20×20日动量 + 25×趋势 + 20×波动率
硬过滤：站上 20 日线，或 60 日动量 > 5%
```

**市场温度**：沪深300 滚动 PE 的历史分位。<30% 偏冷（把现金挪 5% 到权益），>70% 偏热（把 5% 权益挪回现金）。

## 七、资金分配算法（为什么不会超配）

1. 按档位目标权重 × 本金，算出每类资产的**预算**；
2. 每类内部等权分配给入选标的，按最小交易单位向下取整；
3. 剩余零钱在"类别预算上限（目标×1.15）"内按比例补手；
4. 若某类标的不足导致没配够，才动用现金底线（3%）继续补其他类别；
5. 若某个标的占比较高（如保守档可转债只选到 4 只），单只允许超过常规上限，但**不超过该类别在组合中的目标权重**。

任何类别最终都不会超过目标权重的 115%，现金至少保留 3%。

## 八、参数调优：先回测，再改配置

```powershell
# 主回测 + 参数稳健性扫描（20/60/120/180 日窗口 × 持 1/2/3/5 只）
python -m advisor.cli backtest --tier balanced --start 2016-01-01

# 只跑扫描
python -m advisor.cli sweep --tier balanced
```

### 本机实测结果（ETF 池，2016-01 ~ 2026-09，按月调仓，单边成本 5bp）

各档位**当前默认参数**下的表现：

| 档位 | ETF 池 | 动量窗口 / 持仓数 | 年化收益 | 年化波动 | 夏普 | 最大回撤 |
|---|---|---|---|---|---|---|
| 保守型 | 7 只（低风险） | 20 日 / 4 只 | 3.6% | 10.9% | 0.18 | **-23.0%** |
| 稳健型 | 15 只（低+中风险） | 60 日 / 3 只 | 7.0% | 20.4% | 0.26 | -41.3% |
| 激进型 | 26 只（全风险） | 60 日 / 3 只 | — | — | 扫描最优 0.46 | -42.9% |
| 基准 | — | 沪深300 买入持有 | 2.1% | 18.9% | 0.02 | -45.6% |

保守档参数扫描（同一批 7 只 ETF）：

| 动量窗口 | 持仓数 | 年化收益 | 年化波动 | 夏普 | 最大回撤 |
|---|---|---|---|---|---|
| **20** | **5** | 4.2% | 9.8% | **0.25** | **-17.6%** |
| 120 | 5 | 3.0% | 9.7% | 0.13 | -19.8% |
| 60 | 5 | 2.9% | 9.8% | 0.12 | -22.5% |
| 180 | 5 | 2.7% | 9.8% | 0.10 | -19.8% |

诚实的结论：
- **动量轮动在 A 股 ETF 上确实有效**：稳健档年化 7.0% vs 沪深300 的 2.1%，且回撤更小；保守档回撤只有沪深300 的一半。
- **但夏普都不高（0.1~0.46）**，属于"承受高波动换来的一点超额"，不是稳赚。激进档最优组合（60日/持2）年化 12.5%，代价是 -43% 回撤。
- **参数敏感是真实风险**：同一批 ETF，20/60/180 日窗口都还能用，120 日窗口在稳健档明显失效。这说明单一参数的最优值里有运气成分，**不要因为某一组数字好看就上实盘**。
- 默认参数是按上面扫描结果取的"各档位风格上稳健的一组"，不是全局最优（全局最优是过拟合）。你自己可以改。

改参数只需编辑 `advisor/config.py` 里的 `RISK_PROFILES`（每档的权重、上限、过滤阈值、止损止盈都在那一个字典里）。

## 九、每日工作流（怎么用才不出事）

**第一次（只做一次）**：把券商持仓导进来，设置可用现金。

~~~powershell
python -m advisor.cli holdings import --file holdings.csv --cash 50000
~~~

之后不要再重填持仓，除非你真的买卖了。

**每天 5 分钟（收盘后）** —— 两种方式任选：

~~~powershell
# 方式 A：打开界面（推荐）
双击 start_ui.bat   →   确认"我的持仓"   →   点"开始分析"
# 方式 B：命令行（有持仓时自动调仓）
python -m advisor.cli advise --tier balanced --quiet
~~~

打开 reports/YYYY-MM-DD_balanced_调仓日报.md（没持仓时是 决策日报.md），只做三件事：
1. 看"数据体检"有没有失败 —— 有失败就**当天不操作**，先 pip install -U akshare 或检查网络；
2. 按"调仓清单"先卖后买，价格不满足就放弃，不追；
3. 成交后把交易记进账本（trade buy / trade sell），或在界面里改持仓。

**每周**：看一次"备选池"，若持仓跌出前 10 名且触发止损，用备选池第一替补。

**每月首个交易日**：按最新"调仓清单"执行一次，其余时间不动。

### 定时任务（可选）

仓库里附了 `run_daily.ps1`：

```powershell
# 手动跑一次
powershell -ExecutionPolicy Bypass -File .\run_daily.ps1 -Tier balanced -Capital 100000

# 注册为每天 16:30 的计划任务（当日收盘后）
powershell -ExecutionPolicy Bypass -File .\run_daily.ps1 -Tier balanced -Capital 100000 -RegisterTask
```

## 十、风险与局限（务必读完）

1. **规则不是预测**。所有价位由当前价格机械推算，没有考虑突发消息、停牌、强赎公告、评级下调、违约、流动性枯竭。
2. **可转债不是无风险**。低价转债可能是正股 ST、评级 C 的"垃圾债"，本项目虽然过滤了 ST，但**不会预判违约**。买入前请自行查强赎与回售条款。
3. **数据可能出错**。所有数据来自第三方公开网页，字段解读可能随网站改版而失效；报告里的"数据体检"就是用来暴露这个问题的。
4. **回测不等于未来**。回测用等权、忽略冲击成本与停牌，实盘滑点更大。
5. **不要满仓单一类别**。本项目不会主动限制行业集中度，报告里的"集中度"要靠你自己看（银行 ETF + 交通银行 + 兴业银行 是同一风险源）。
6. **不做自动下单**。没有任何券商接口，全部需要你手动确认后下单——这是刻意的设计。
7. **不提供税务、合规、适当性建议**。

## 十二、常见问题

**Q：报错 `ProxyError ... eastmoney.com`？**
A：这是东财 push2 域名被网络/代理拦截，属于预期情况。代码已自动降级到新浪/腾讯，不影响使用。若所有源都失败，先跑 `python -m advisor.cli data-check` 定位。

**Q：界面打不开 / 端口被占用？**
A：换端口 `python -m advisor.cli ui --port 8899`；界面只监听本机 127.0.0.1，其他设备访问不到是正常的（也不建议暴露到局域网）。

**Q：AI 复核报 `HTTP 401`？**
A：Key 不对或已失效，去 platform.deepseek.com 重新生成。报 `HTTP 402` 是余额不足；报连接错误就检查 Base URL 与代理。

**Q：某类资产实际权重远低于目标？**
A：看报告第一部分下面的"今日无标的/标的不足的原因"。规则筛不出标的是常态（尤其成长股在市场下跌时），此时钱留在现金里，这是纪律。

**Q：持仓在哪里改？**
A：界面第二个卡片"我的持仓"直接增删改，点"保存持仓"；或命令行 holdings import / holdings add / trade buy / trade sell。数据在 data/advisor.db，删掉它等于清空账本。

**Q：为什么调仓清单要卖出我持有的票？**
A：两条原因：一是不在本期候选池（规则不再推荐），二是超配（目标数量小于当前）。不想自动清仓就加 --keep-unknown；想先看看目标组合、不急着卖，用 --mode build 对照。

**Q：保存持仓会覆盖什么？**
A：覆盖的是"持仓快照"：先清空 transactions 再按表格写入 opening 记录。现金只有填写后才更新。想保留连续交易流水，用 trade buy / trade sell 记账，不要反复点保存。

**Q：我填了 --capital，为什么调仓模式没用？**
A：调仓模式的本金 = 持仓市值 + 现金，不再用 --capital 当本金；--capital 只在 --mode build 或没有持仓时生效。

**Q：想加自己的股票池？**
A：改 `advisor/config.py` 的 `DIVIDEND_CANDIDATES` / `GROWTH_CANDIDATES`，或直接给 `ETF_UNIVERSE` 加 ETF（格式 `sh510300: {name, tag, risk}`）。

**Q：想每天自动留档？**
A：`run_daily.ps1 -RegisterTask`，报告按日期命名不会被覆盖；也可以在界面里点"历史报告"翻看与下载。
